# ConvertTool

文字格式转换工具。把 PDF（文本型 / 扫描型均可）转成 **TXT** 纯文本或 **EPUB** 电子书，
支持把「多本拼合」的 PDF **自动拆分**成一本本独立的书。带 tkinter 图形界面。

## 文件说明

| 文件 | 作用 |
|------|------|
| [convert_gui.py](convert_gui.py) | 图形界面（tkinter）。运行入口。 |
| [pdf_tool.py](pdf_tool.py) | 转换引擎：按页区间提取、OCR 缓存、EPUB 生成、分界点检测。复用 `pdf2txt.py`。 |
| [pdf2txt.py](pdf2txt.py) | 底层转换核心（横排/竖排重建、页眉页脚剥离、软换行合并、OCR、繁简转换）。 |

## 快速开始

```bash
# 依赖（PyMuPDF 已装则只需补这两步；OCR/繁简为可选依赖）
pip install PyMuPDF rapidocr zhconv

python convert_gui.py
```

界面操作：

1. **① 输入 PDF**：选择文件。扫描版会自动识别并提示需要 OCR。
2. **② 拆分**：点「自动检测分界」——程序扫描全书页面留白，几秒定位每本书的页码区间并 OCR 扉页取书名。
   区间和书名都可手动改；`✕` 删除一行。不拆分则整本输出。
3. **③ 输出**：选 TXT 或 EPUB，选输出目录。
4. **④ 转换选项**：扫描书保持「OCR 识别」开启；可选合并软换行、繁体转简体、版面（自动/横排/竖排）。
5. **⑤ 开始转换**：后台线程跑，实时进度 + 日志，可随时「停止」。

## 它是怎么拆书的

扫描版小说合集没有目录书签，程序靠**页面留白**自动拆分：

- 正文页文字密集（非白像素比例高），封面 / 扉页 / 空白页大面积留白；
- 章节之间的空白通常只有 1 页，而**两本书之间会有 ≥2 页连续空白**（含扉页/版权页）——这就是分界信号；
- 程序据此把全书切成大段正文区块，每个区块回溯到前面的扉页作为起始页，再 OCR 扉页取书名。

针对仓库内的 `1-2-3-4-5.pdf`（850 页扫描版，实为 4 本民国鸳鸯蝴蝶派小说），自动检测结果：

| 书 | 页码 |
|----|------|
| 玉梨魂（徐枕亚） | 1 – 220 |
| 孽冤镜（双热） | 221 – 373 |
| 贾玉怨（李定夷） | 374 – 548 |
| 雪鸿泪史（枕亚） | 549 – 850 |

> 第 1 本的扉页埋在前言里，书名可能自动识别不到，手动填一下即可。

## 性能说明

- OCR 是瓶颈。850 页扫描书首次全量 OCR 仍需较长时间（视 CPU 而定）。
- **多进程并行 OCR**：扫描页的 OCR 提交到进程池（默认「CPU 核数 / 2」个进程并行，
  可在「并行进程」里调）。实测 8 核机约 **2 倍** 提速。
  - 单页 OCR 本身已能吃满多核（ONNX 用全部线程），所以并行提速幅度有限；
    **想更快，把「OCR DPI」从 300 调到 200 提速更明显**（小字密集的书仍建议 300）。
  - 进程池里每个 worker 处理一批页后被回收（`max_tasks_per_child`），**释放 ONNX 内存池**，
    彻底解决「扫描书跑几百页后内存爆掉、第二本书崩」的问题。
  - 每个 worker 的 ONNX 线程数按 worker 数自动分配（`核数 // worker 数`），避免超订；
    rapidocr 的 params 改不了这个值，所以是在 worker 里 monkeypatch ONNX 的 SessionOptions 实现的。
- **逐页 OCR 缓存**：每页 OCR 结果存到 `<pdf 同目录>/.<文件名>_ocrcache/`，
  二次运行（改格式、调选项、重新拆分）命中缓存近乎免费。
- **留白扫描缓存**：分界检测的页面密度数据存到 `.<stem>_density.json`，二次检测秒开。

## 文本质量说明（扫描书）

OCR 出来的原始文本会带两类瑕疵，程序已自动处理：

- **页码粘连**：OCR 把页码（如 `160`）单独识别成一行，若不处理会被「合并软换行」
  拼进正文，出现 `鹃化175眼`（页码夹在词中间）。程序逐页剥离独立成行的页码。
- **章节标题粘连**：章名（如 `第二十三章`）若不处理会和正文粘成
  `第二十三章君多情人也`。程序让章名独占段落，并修补跨页拼接造成的残留粘连。

> 目录（TOC）页因为是「章名 + 页码 + 省略号」的列表，无法可靠区分，仍会有些粘连，
> 属已知局限；正文和真正的章节起点都会正确分段。

## 命令行

底层核心 `pdf2txt.py` 本身是完整的命令行工具，无需 GUI 也能用：

```bash
python pdf2txt.py 输入.pdf                       # 文本型 PDF → 同名 .txt
python pdf2txt.py 扫描书.pdf --ocr               # 扫描型走 OCR
python pdf2txt.py 繁体书.pdf --ocr --t2s         # OCR + 繁转简
python pdf2txt.py 资料/ -o out/                  # 批量转换整个目录
```

## 依赖

- Python 3.10+（在 3.14 上测试通过）
- PyMuPDF（`fitz`）—— 必装
- rapidocr（PP-OCRv6）—— 扫描书 OCR 用，可选
- zhconv —— 繁体转简体，可选
- tkinter —— Python 标准库自带
